# 일정관리 개편 구현 계획

1. `tests/schedule-domain.test.js`에 비파괴 정규화, 계약 현장 ID 중복 방지, 정확한 견적 키 판독, 모든 공정 분리·병합 규칙, 욕실 순서, 충돌 판정 테스트를 먼저 작성한다.
2. `schedule-domain.js`에 테스트를 통과하는 순수 도메인 함수와 중앙 규칙 레지스트리를 구현한다.
3. `schedule-holidays.js`에 내장 대한민국 공휴일 공급자와 실패 안전 병합 인터페이스를 구현하고 fallback 테스트를 추가한다.
4. `schedule.html`의 기존 배열 저장을 보존한 채 일반 일정 전용 `daham_schedule_general_v1` 로컬/Supabase 동기화를 추가하고 양쪽 저장소 독립 동작을 테스트한다.
5. 계약 현장 자동 연결을 실제 프로젝트 ID와 상태 판정으로 교체하고 신규 수동 현장 생성 UI를 제거한다. 기존 수동 현장은 읽기·편집 가능 상태로 유지한다.
6. 현장 카드, 전체 월간 공사/일반 일정, 견적 공정 후보 편집, 메모, 작업자 충돌 경고와 owner 확인 저장 UI를 구현한다.
7. PC·태블릿 월간 달력과 모바일 agenda/list 반응형 화면을 구현하고 인쇄 규칙을 보호한다.
8. 전체 자동 테스트와 기존 회귀 테스트를 실행하고 실패를 수정한다.
9. 지정된 여섯 viewport에서 실제 브라우저로 기능, overflow, 콘솔 오류를 검증한다. Supabase 운영 데이터는 쓰기 테스트 전에 스냅샷을 보존하고 테스트 데이터만 회수한다.
10. 모든 검증 통과 후 기능 커밋, 원격 브랜치 게시, main 병합, Pages 완료 확인, 실제 도메인 smoke test를 수행한다.
