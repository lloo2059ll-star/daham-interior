# 포트폴리오 사진 전면 재구성 설계

## 목표

현재 8개 시공 프로젝트의 명칭·지역·평수·종류는 유지하면서, 제공된 실제 시공 원본 129장을 공간 종류와 품질로 다시 선별해 대표사진과 상세사진을 재구성한다. 고객이 각 현장의 거실·주방뿐 아니라 욕실, 현관, 방, 수납, 복도, 베란다와 마감 디테일까지 이해할 수 있어야 한다.

## 확인된 현재 구조

- `index.html`은 `portfolio-static-domain.js`를 읽어 정적 카드 4개를 먼저 표시한다.
- `website-final.js`는 Supabase `website_portfolio` 공개 행이 있으면 메인 카드 4개를 대표 이미지 URL 기반으로 교체한다.
- `portfolio.html`과 `portfolio-page.js`는 Supabase를 읽지 않고 `portfolio-static-domain.js`의 정적 프로젝트와 사진 배열만 사용한다.
- `portfolio-static-domain.js`는 프로젝트별 사진 수만 받아 `01.webp`부터 연속 번호를 자동 생성한다. 실제 노출 가치를 표현하는 순서 데이터가 없다.
- `portfolio-assets/projects/<slug>/`가 현재 정적 대표사진과 상세사진의 실제 저장 위치다.
- `website-admin.html`은 `website_portfolio`의 공개 메타데이터와 대표 이미지 URL만 관리하며 상세사진 업로드·순서·삭제 기능은 없다.
- 제공 ZIP 8개에는 실제 시공사진 129장이 있다. 현재 정적 상세에는 60장만 사용되며, 봉곡 현진에버빌의 현재 대표사진은 제공된 해당 현장 원본과 일치하지 않는다.

## 사진 선별 원칙

각 프로젝트는 대표 전체 공간, 거실, 주방, 욕실, 현관, 방, 수납·가구, 마감 디테일 순으로 구성한다. 원본에 특정 공간이 없으면 존재하지 않는 이미지를 만들거나 다른 현장 사진으로 대체하지 않는다. 같은 위치와 구도가 반복되는 사진은 제외하고, 서로 다른 공간 정보가 보이는 경우에만 같은 공간 사진을 추가한다.

대표사진은 밝기, 수평·수직, 공간감, 완성도와 프로젝트 간 다양성을 기준으로 고른다. 세로 디테일 사진은 대표사진으로 사용하지 않는다. 모든 결과물은 제공 ZIP의 실제 시공사진만 사용한다.

## 프로젝트별 방향

- 구미 푸르지오캐슬 A단지 32평: 거실·주방 연결 전경을 대표로 사용하고, 욕실 2곳, 방, 드레스룸, 복도, 거실, 주방, 아일랜드와 석재 디테일을 포함한다.
- 거창 푸르지오 34평: 우드 주방까지 연결되는 밝은 거실을 대표로 사용하고, 거실, 주방, 욕실 2곳, 현관, 방, 복도와 간접조명 디테일을 포함한다.
- 봉곡 현진에버빌 36평: 잘못 연결된 기존 대표사진을 제거하고 주방·복도가 연결된 거실 전경을 대표로 사용한다. 거실, 주방, 욕실 2곳, 현관, 방, 복도와 수납을 포함한다.
- 임은동 코오롱하늘채 35평: 벽면 수납과 조명이 함께 보이는 거실을 대표로 사용하고, 거실, 주방, 욕실 2곳, 현관 수납, 방, 화장대, 베란다를 포함한다.
- 송정 주택·상가 23평: 거실에서 주방까지 보이는 전경을 대표로 사용하고, 거실, 주방, 욕실 2곳, 현관 중문, 수납가구를 포함한다.
- 옥계 e편한세상 35평: 주방·다이닝·거실이 연결된 전경을 대표로 사용한다. 원본에 욕실과 현관 사진이 없으므로 거실, 주방, 다이닝, 방, 화장대·수납을 균형 있게 구성한다.
- 송정동 동양한신 42평: 수평이 안정된 거실 전경을 대표로 사용하고, 거실, 주방, 복도, 수납가구와 조명 흐름을 포함한다. 제공 원본에 욕실·현관 사진은 없다.
- 대구 화성 상인화이츠: 거실과 주방 흐름이 보이는 전경을 대표로 사용하고, 거실, 주방, 욕실, 방의 붙박이장과 복도를 포함한다.

## 데이터와 관리자 설계

정적 데이터는 사진 수 기반 자동생성을 폐기하고, 프로젝트별 `coverImage`와 명시적인 `photos` 배열을 저장한다. 사진은 의미가 드러나는 파일명으로 저장해 향후 순서를 이해할 수 있게 한다.

Supabase `website_portfolio`에는 상세사진 URL 순서를 담는 `gallery_image_urls jsonb`를 추가한다. 값은 문자열 URL 배열이며 기본값은 빈 배열이다. 공개 사용자는 공개된 행만 읽고, 인증된 활성 직원만 수정하는 기존 RLS 원칙을 유지한다.

관리자는 기존 ERP 프로젝트와 현재 정적 포트폴리오 프로젝트를 함께 선택할 수 있다. 상세사진 URL을 추가·삭제하고 위/아래로 이동하며, 목록 중 하나를 대표사진으로 지정할 수 있다. 별도 Storage 업로드 시스템은 만들지 않는다. 현재 프로젝트의 실제 파일은 저장소에 유지하고 관리자는 그 공개 경로와 순서를 관리한다.

공개 상세 페이지는 동일한 slug의 공개 Supabase 행에 비어 있지 않은 갤러리 배열이 있으면 이를 사용하고, 데이터베이스 오류·미적용·빈 배열이면 정적 선별 데이터를 사용한다. 따라서 마이그레이션 적용 전이나 네트워크 장애에도 포트폴리오가 정상 표시된다.

## 반응형 이미지 처리

카드 대표사진은 기존 고정 비율과 `object-fit: cover`를 유지하되 프로젝트별 `coverPosition`을 선택적으로 적용해 핵심 부분 잘림을 방지한다. 상세 갤러리는 이미지 원본 비율을 보존하고 최대 폭만 제한한다. 세로사진은 확대 크롭하지 않으며 PC 2열, 모바일 1열 흐름을 유지한다.

## 오류 처리와 검증

- 존재하지 않거나 디코딩할 수 없는 사진은 자동검사에서 실패시킨다.
- 정적 프로젝트 8개, 고유 slug, 대표사진, 명시적 상세 배열과 파일 존재를 검사한다.
- 관리자 도메인은 URL 정제, 빈 항목 제거, 중복 제거, 순서 보존을 검사한다.
- DB 마이그레이션은 jsonb 배열 제약과 기존 RLS 유지 여부를 검사한다.
- 공개 페이지는 Supabase 갤러리 우선, 정적 fallback, 로딩 실패 표시를 검사한다.
- 로컬 브라우저에서 PC, 태블릿, 모바일 뷰포트로 카드 크롭, 상세 비율, 모달, 깨진 이미지를 확인한다.

## 범위 제외

홈페이지 전체 디자인, 폰트, 메뉴, 회사소개, 공사과정, 서비스, 고객후기, 견적문의, ERP의 다른 기능은 수정하지 않는다. 인터넷·스톡·AI 생성·타 업체 이미지는 사용하지 않는다.
