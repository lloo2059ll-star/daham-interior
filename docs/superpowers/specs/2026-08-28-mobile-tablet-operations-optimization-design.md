# 운영 페이지 모바일·태블릿 최적화 설계

## 목적

현재 배포된 운영 페이지의 데스크톱 디자인과 모든 업무 기능을 유지하면서 모바일과 태블릿에서만 사용성을 개선한다. 새 반응형 계층은 기존 운영 전용 `operations-ui.css` 안에 격리하며 인증, Supabase, 권한, CRUD, URL, 데이터 구조와 인쇄 결과를 변경하지 않는다.

## 수정 금지 범위

다음 파일은 작업 전후 SHA-256이 동일해야 한다.

- `index.html`
- 모든 `estimate*.html`
- `v2-theme.css`
- `v2-suite.css`
- `v2-suite.js`
- `consult-demo.html`
- `design-demo.html`
- `index.prototype.html`

기준 페이지와 견적 계열이 참조하는 자산도 변경하지 않는다. 반응형 작업은 운영 페이지만 불러오는 `operations-ui.css`와 승인된 운영 HTML의 표시용 body 클래스에 한정한다.

## 선택한 접근

`operations-ui.css`의 기존 데스크톱 규칙을 유지하고 그 뒤에 `@media screen` 기반 반응형 계층을 추가한다. 공통 규칙으로 해결할 수 없는 고유 레이아웃에는 표시 전용 body 어댑터 클래스를 추가한다. 기능 DOM이나 JavaScript 렌더링 구조는 재구성하지 않는다.

## 반응형 구간

- 모바일: `360px`부터 `430px`
- 소형 태블릿: `431px`부터 `767px`
- 일반 태블릿: `768px`부터 `1024px`
- 데스크톱: `1024px` 초과

규칙은 작은 화면 우선 재작성 대신 기존 데스크톱 스타일 위에 `max-width` 어댑터로 적용한다. `1024px` 초과에서는 새 반응형 선언이 적용되지 않아 현재 데스크톱 디자인이 유지된다. 경계값 430, 431, 767, 768, 1024px에서 간격과 배치가 급격히 바뀌지 않도록 동일한 토큰과 점진적 grid/flex 전환을 사용한다.

## 공통 사용성 규칙

### 폭과 여백

- 운영 콘텐츠 폭을 viewport 안에 제한하고 좌우 여백을 모바일 10~12px, 태블릿 16~20px로 조정한다.
- flex/grid 자식에 `min-width: 0`을 적용해 긴 문자열이 부모 폭을 강제로 넓히지 않게 한다.
- 이메일, 주소, 현장명과 메모에는 `overflow-wrap: anywhere`를 적용한다.
- 금액과 날짜는 의미를 보존해야 하므로 셀 내부 줄바꿈 또는 표 영역 가로 스크롤을 사용한다.

### 터치 대상

- 기능 버튼, 입력, 선택창은 모바일·태블릿에서 최소 44px 높이를 확보한다.
- 아이콘 버튼은 최소 40×40px 클릭 영역을 확보한다.
- 버튼 그룹은 `flex-wrap`과 8px 이상의 간격을 사용해 겹침을 방지한다.
- 체크박스, 라디오, 문서 내부 고정 크기 입력은 공통 높이 규칙에서 제외한다.

### 헤더·필터·액션

- 모바일에서는 제목과 액션을 세로로 배치하고 액션 버튼을 1열 또는 2열로 확장한다.
- 태블릿에서는 제목과 주요 동작을 유지하되 검색·필터 그룹만 다음 줄로 이동한다.
- 단가 조정표처럼 `.top`과 `.toolbar`가 일반 페이지 의미와 다른 화면은 기존 전용 어댑터를 확장한다.

### 모달

- 모달 외곽은 `100dvh`를 넘지 않으며 상하 안전 여백을 둔다.
- 모달 본문만 스크롤되고 헤더·하단 동작은 접근 가능한 위치에 유지한다.
- 모바일 하단 시트와 태블릿 중앙 모달 전환은 기존 열기/닫기 DOM과 이벤트를 그대로 사용한다.
- 가상 키보드가 나타날 때 입력 필드가 모달 밖으로 밀리지 않도록 본문에 `overscroll-behavior`와 내부 스크롤을 적용한다.

### hover 대체

- hover로만 표시되는 행 동작과 오버레이 버튼은 `hover: none` 또는 모바일 구간에서 항상 표시한다.
- `:active`와 `:focus-visible` 피드백을 유지해 터치와 키보드 접근을 함께 지원한다.

## 테이블 전략

테이블 데이터와 CRUD DOM은 카드 마크업으로 재구성하지 않는다.

- 상담, 결제, 단가표와 문서 표는 기존 표 구조를 유지하고 외곽 컨테이너에 안전한 가로 스크롤을 적용한다.
- 기존에 모바일에서 숨기도록 지정된 보조 열만 그대로 숨긴다. 필수 열은 새로 숨기지 않는다.
- 스크롤 영역에는 `-webkit-overflow-scrolling: touch`, `overscroll-behavior-inline: contain`과 시각적 경계를 적용한다.
- 직원관리는 이미 grid 행 기반이므로 기존 행 DOM을 그대로 둔 채 800px 이하에서 카드형 grid 배치만 정돈한다.
- 긴 셀은 최소 폭과 줄바꿈을 조합하고 삭제·승인·권한 버튼은 같은 행에서 유실되지 않게 한다.

## 페이지 유형별 처리

### 관리 화면

공통 헤더, 검색, 필터, 요약 카드, 데이터 목록과 모달을 반응형 계층으로 보정한다. 상담 삭제와 직원 권한 버튼의 가시성은 기존 역할 판정 결과를 그대로 따른다.

### 사진·일정·업무일지

카드 grid 열 수를 viewport에 맞춰 점진적으로 줄이고, 일정 툴바와 날짜 이동 버튼은 줄바꿈한다. 사진 오버레이 동작은 터치 환경에서 항상 접근 가능하게 한다.

### 문서·출력

새 규칙은 `@media screen` 안에서만 적용한다. 편집 툴바와 화면 미리보기 컨테이너만 반응형으로 만들고 A4 문서 본문은 축소 재배치하지 않는다. 좁은 화면에서는 문서 본문을 가로 스크롤로 탐색한다. 기존 `@media print`, 용지 크기, 페이지 나눔, 입력 위치와 출력 내용은 변경하지 않는다.

### 로그인

모바일에서는 이미지 영역을 숨기는 기존 동작을 유지하고 폼 폭, 입력 높이, 탭, 도움말과 footer 간격을 최적화한다. 태블릿에서는 폼이 지나치게 좁아지거나 화면 높이를 강제로 넘지 않게 한다. 로그인·가입·승인 대기 DOM과 흐름은 유지한다.

## 기능 보존

- 스크립트 `src`, 요소 ID, 폼 `name`, inline 이벤트, 링크와 인쇄 블록 시그니처를 유지한다.
- Supabase URL, 키, 요청, 테이블, RPC와 RLS 연계 코드를 변경하지 않는다.
- 인증, 역할 판정과 버튼 표시 로직을 변경하지 않는다.
- CRUD 함수, 데이터 렌더링 컨테이너와 localStorage 키를 변경하지 않는다.
- 테이블 행과 셀을 JavaScript로 다른 모바일 DOM에 복제하지 않는다.

## 테스트 전략

### 자동 검사

- 보호·제외 파일 SHA-256 기준값 일치
- 운영 페이지 기능 시그니처 일치
- 새 미디어 규칙이 `screen` 안에만 존재하고 `1024px` 초과에 적용되지 않는지 검사
- 모바일·태블릿 터치 높이, 모달 최대 높이, 긴 문자열, 표 스크롤 규칙의 CSS 계약 검사
- 기존 전체 인증·권한·CRUD·Supabase·보안 테스트 실행
- 인쇄 블록 수와 기능 hook 불변 검사

### 실제 브라우저

아래 viewport를 각각 고정해 대표 관리·문서·인증 화면을 확인한다.

- `390×844`
- `430×932`
- `768×1024`
- `820×1180`

각 viewport에서 `scrollWidth <= clientWidth`인 일반 페이지, 의도된 표/문서 내부 스크롤, 터치 대상 크기, 헤더와 필터 겹침, 모달 경계, 긴 문자열, hover 대체 상태와 콘솔 오류를 검사한다. 표/문서 내부의 명시적 스크롤은 페이지 전체 가로 스크롤과 구분한다.

데스크톱은 최소 `1280×720`과 `1440×900`에서 기존 주요 computed style과 레이아웃을 비교한다. 문서 페이지는 화면 반응형과 별도로 인쇄 스타일 격리를 자동 검증한다.

## 배포

검증을 통과한 변경만 기능 브랜치에 커밋한다. HTTPS Git 전송은 사용하지 않고 GitHub API로 원격 기능 브랜치와 `main`을 갱신한다. GitHub Pages 실행이 병합 커밋을 대상으로 성공한 뒤 실제 `https://daham-interior.com`에서 HTTPS, 새 CSS, 로그인과 미인증 내부 페이지 리다이렉트, 대표 운영 페이지 자산을 확인한다.
